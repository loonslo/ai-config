# 桌面界面布局优化

维护与实际验证日期：2026-10-11。

## 范围与设计

用户要求调用前端 UI 技能优化整个页面布局。本次读取本机 frontend-design 技能，检查当前 React/Tauri 三页、既有 CSS、窗口尺寸和 ui-test 夹具。沿用既有组件和本机协议，改动展示结构；不新增依赖或修改后端采集、预览、写入与撤销逻辑。开始前将三个已有页面源文件的当前版本另存于本项目临时目录，保留已有未提交工作。

界面服务于换机备份与恢复。采用深蓝导航与浅色工作区，主操作为蓝色；不使用远程字体或素材，离线运行仍使用本机中文字体。

- 色彩：工作区 `#f3f5f9`，面板 `#ffffff`，正文 `#243044`，次要文字 `#647187`，操作 `#4265ce`，导航 `#202c40`。
- 字体：Segoe UI Variable / Segoe UI / Microsoft YaHei UI / PingFang SC；标题 25–32 px，步骤 17 px，选项与按钮 13 px；辅助说明使用较小字号。
- 布局：左侧导航；备份主区按真实操作顺序分为选择助手、选择内容、工作文件夹、保存位置。前两个步骤在左，项目、保存位置与检查入口在右。默认 940×700 窗口保留两列，900 px 及以下上下排列，760 px 及以下导航转为顶栏，480 px 及以下选项单列。
- 层次：选中、未找到、禁用、正在处理分别呈现。结果独立成区，核验失败使用红色提示且展开失败组。保留已有预览与确认门禁。

```
导航 | 页面标题、说明                         重新检测
     | 1 选择助手            | 3 工作文件夹
     | 2 选择备份内容        | 4 保存位置
     |                     | 检查备份内容
     | 检查结果、差异与确认
```

对初稿的调整：依据实际默认窗口宽度，将两列切换点从 1120 px 收紧为 900 px，940 px 下仍可并排看到保存位置；用不同层级的分区、分隔线和实际步骤替代一个长面板。恢复的 ZIP 入口、已有配置选择、核验详情及恢复记录空态使用同一视觉系统。UiIcon 为本地 SVG 组件。

## 验证

环境：Windows、现有 desktop 依赖、Vite 8.3.1、TypeScript、React；浏览器连接 localhost ui-test，全部助手、路径和响应为既有合成 Fixture 数据。

- 最终 `npm run build` 与 `npm run lint` 均退出 0。生产产物为 `index-Dfj3RLoM.css`、`index-DWlK2Q5f.js`；不包含 ui-test 传输替身。
- 备份页及恢复完成报告在 320、360、700、940、1200、1600 px 六种宽度检查：document scrollWidth 未超出窗口；可见按钮、标签、路径、标题和面板无越界。940 px 默认窗口保留两列；360 px 记录页无横向溢出。
- 未选保存位置时检查按钮禁用；选择合成文件夹后启用，预览结果显示生成确认入口。模拟确认验证完成提示和确认入口消失。既有 sync-groups 夹具在 apply 时没有保存备份 operation，返回的明细属于恢复结构，因此该次模拟确认仅用于检查界面状态，不作为备份完成明细或后端验收证据；没有为本轮修改夹具。
- 恢复未选 ZIP 时检查禁用；选择后可检查。restore-choices 夹具未处理冲突时确认禁用，全部覆盖后自动更新期间禁用，更新完成后启用；模拟恢复后按类型折叠 26 个技能文件及人工加载确认项。
- restore-fail 夹具选择全部保留后可确认；模拟核验失败时显示失败数量、红色主提示（rgb(173,60,53)）和自动展开的失败详情，结果容器使用 is-attention。
- 恢复记录显示有说明的空态；主导航能正常切换。浏览器最后 error 日志为空。
- 人工查看桌面备份与窄屏截图，未见重叠；截图为合成响应的 UI 预览。截图 API 初次与尺寸覆盖不一致，改用相同尺寸的 viewport 与 CDP capture 后重新保存；不采用裁剪错误的初稿。临时浏览器页、尺寸覆盖和 Vite 服务已清理。
