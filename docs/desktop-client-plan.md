# 桌面客户端与跨设备迁移方案

日期：2026-10-01。状态：方案已列出；Windows 客户端原型已有本机入口，DT-13～16 的包格式、采集边界、核心导出和只读安全检查已实现，仍未通过原生窗口或跨设备验收。目录映射、导入客户端流程和服务端尚未实现。逐步工作、依赖和完成条件见 [40 项实施任务](../DESKTOP-TASKS.md)；本文件描述各任务要实现的系统如何运行。

## 1. 产品目标与约束

用户提出的方向：像 CC Switch 一样，以桌面客户端作为统一操作入口；所有功能操作在客户端完成。跨设备支持两种方式：登录用户提供的服务器上传／下载，以及全量导出后自行复制到另一台电脑并导入。导入时调整各 agent 的目录。

客户端应覆盖首次设置、agent 识别与迁入、规则编辑、配置应用、差异处理、导出／导入、云端同步、状态、撤销与恢复，以及可选的记忆和项目接续。正常使用无需手工编辑 JSON、执行终端命令或克隆工具源码。账号只用于云端同步，离线功能无需登录。

当前仓库提供 Python 核心与 CLI，并已建立 Tauri/React Windows 客户端原型；全功能图形客户端尚未交付。现有 Git 同步保留为兼容入口，不作为新用户必须理解或安装的前置条件。

“全量”定义为所选范围内全部受支持、可迁移的数据；导出清单必须同时列出纳入、排除和未支持项。不递归复制整个 `.codex`、`.claude` 或其他 agent 运行目录。目标电脑仍需安装相应 agent，并完成本机登录及必要的依赖安装；客户端展示未满足条件，不能笼统承诺原生会话完整恢复。

## 2. 架构与职责

```text
桌面客户端
  ├─ 操作页面、预览、进度、冲突选择与结果
  └─ 本机应用服务
       ├─ 既有 sync_core：识别、迁入、规划、事务、核验、撤销
       ├─ 新迁移包层：导出、完整性检查、暂存、导入规划
       ├─ agent 适配层：数据范围、逻辑路径、本机目录、版本兼容
       └─ 传输层
            ├─ 离线：导出目录／归档、读取复制来的迁移包
            └─ 云端：登录、上传、下载、版本与设备回执
```

当前实施起点为 Tauri 2 + React + TypeScript + Vite，既有 Python 核心随安装包作为本机辅助程序分发。Tauri 官方支持嵌入外部程序，但本项目尚未验证各平台打包。先做 Windows 垂直流程，再验证 macOS 构建、签名与安装。DT-05 验证后锁定技术与依赖版本；必要的替代方案记录原因，不先重写可靠性核心。

界面通过受限、结构化的本机接口调用服务，不接受任意 shell 命令；业务结果和进度事件独立于 CLI 展示文字。复用事务与核验能力，不以解析中文终端输出实现界面。安装包内置所需核心运行环境；离线主流程不依赖用户安装 Python 或 Git。

本机状态：设备身份、实际目录、账号令牌、基线、事务和备份，仅保存在本机。可迁移内容：版本化快照及逻辑映射。云端状态：用户归属、包版本、设备回执及上传状态，不决定目标电脑的实际文件路径。

## 3. 客户端操作流程

| 页面 | 用户操作与可观察结果 |
| --- | --- |
| 总览 | 显示各 agent 的识别、应用、需重开会话、加载核验状态；分别显示上传／下载状态 |
| agent 与配置 | 检测目录、迁入已有规则、编辑共享规则、选择共享或仅本机、预览并应用 |
| 跨设备迁移 | 导出完整迁移包、选择本地包导入；列出包含项、排除项、路径映射与冲突 |
| 云端同步 | 登录、上传当前快照、下载指定版本、查看设备回执与历史版本 |
| 历史与恢复 | 查看操作、备份与版本；预览撤销／恢复并执行 |
| 可选功能 | 启用记忆、映射项目、查看交接及缺失条件；未启用不阻塞配置 |

离线流程：A 客户端导出 → 用户复制整个导出目录或归档 → B 客户端打开包 → 检测并映射目录 → 展示导入预览 → 用户点击应用 → 备份、写入、核验。

“拆包即用”的产品体验是打开迁移包后由客户端完成适配和应用，无需用户逐个改 agent 目录；普通解压程序无法可靠完成目录映射。可后续注册包关联实现双击导入，不能依靠自动执行包内脚本。

## 4. 两种同步共用的迁移包

建议采用版本化目录格式，并提供单文件归档方便复制。首次实现先保证完整快照，自包含且可离线导入；后续可优化传输，不改变恢复语义。

```text
export/
  manifest.json          # 格式版本、包 ID、逻辑来源、父版本、文件清单与校验值
  config/                # 公共规则与受支持的共享配置
  agents/                # 可迁移的 agent 声明与结构化设置
  skills/                # 后续适配支持的技能内容，去重保存
  memory/                # 可选且通过范围检查的记忆快照
  handoffs/              # 可选的项目接续资料
  report.json            # 纳入、排除、未支持项及未满足的依赖
```

此结构是新格式草案，不表示 skills、MCP 或完整设置迁移已支持。清单至少包含相对路径、数据类型、agent／实例 ID、大小、内容哈希、适配器版本和依赖声明；不携带源机器绝对路径、登录身份或本机设备配置文件。

| 数据 | 处理方式与当前边界 |
| --- | --- |
| 公共规则、已支持的共享设置、agent 声明 | 首期迁移范围；本机根目录从声明中剥离后重建 |
| skills | 后续扩展；识别链接、收集明确纳入范围的真实内容、目标端重建；当前仅盘点 |
| MCP 设置 | 后续按适配器迁移非敏感字段；密钥只保留变量引用，本机命令及依赖重新核对 |
| 记忆与项目交接 | 可选；沿用已验证格式与来源标识，不回填未知原生数据库 |
| API Key、令牌、Cookie、认证及私钥 | 排除；目标端本机登录／配置，服务账号令牌使用本机安全存储 |
| 会话数据库、缓存、锁、日志、临时文件、运行状态 | 排除；不复制工具整个运行目录 |
| 项目源码、工具安装包、外部程序依赖 | 首期不纳入配置迁移；列明需要重新取得的内容 |

导出先得到一致快照，源文件在采集中变化时重新规划或停止，不能产出混合版本。未知文件不得仅因位于 agent 目录而自动加入。既有受保护文件不因新增导出功能变成可读来源。

## 5. 目标电脑目录适配

包内以 `agent://<类型>/<实例>/<相对入口>`、`store://<相对路径>`、`project://<项目ID>/<相对路径>` 等逻辑引用表达位置，设备本机生成实际路径映射。例如 Codex 的逻辑规则入口映射到目标设备检测到的 Codex 根目录，不携带发送设备的用户名和盘符。

默认目录自动检测；自定义目录、多个实例和项目工作区通过客户端选择。创建新的目标设备身份，不复用发送设备 ID、事务、回执或本机基线。未安装的 agent 标记为待安装，包保留在客户端配置库，安装并识别后再应用。

仅重写适配器声明的路径字段；不全文替换用户名或盘符。普通规则、代码和记忆中可能有历史路径，无法确定语义时列为待处理项。Windows／macOS 间的大小写、Unicode、非法文件名、命令和外部依赖必须核对。

符号链接与 Windows junction 不原样搬运。支持的技能链接先在受限范围内解析来源，再保存内容与关联，导入时重建；外部链接、链接循环及 CC Switch 接管冲突先展示处理方案，不能越界遍历或覆盖另一管理工具的数据。

导入流程：格式／版本与完整性检查 → 安全暂存 → 本机目录映射 → 差异与依赖检查 → 预览 → 备份与事务应用 → 内容核验 → 需要时的新会话加载核验。对路径穿越、越界链接、重复或碰撞路径、异常展开体积、损坏及不兼容包在写目标前停止。

## 6. 用户服务器同步

客户端上传同一种完整快照；另一设备登录后下载并走同一导入流程。服务器地址、部署环境、登录方式、容量与保留策略尚未提供，当前只定义职责，不连接或部署真实服务。

服务端负责身份认证、每用户授权隔离、包存储、版本索引、配额、上传完成确认与回执；不远程执行本机命令，也不生成目标电脑路径。只授权用户自己的包，不能凭包 ID 访问其他用户数据。

上传分为暂存与完成确认，未完成对象不进入可下载版本列表。使用不可变版本及父版本检查；两台设备从同一父版本分别修改时保留双方并提示冲突，不按上传时间覆盖。首次下载缺少共同基线时先比较并让用户选择，不假定可以直接覆盖本机内容。

建议客户端加密后上传，以减少服务器接触个人规则和记忆的范围；加密协议、跨设备解锁与恢复方式需在云端实施前确定。登录与解密能力分开设计，不能声称“登录即可解密”而缺少密钥获取机制。离线未上传、云端已保存、本机已应用、加载已核验分别展示。

### 新接口和状态约定

Rust 外壳管理单个 Python 辅助程序，通过标准输入／输出交换按行 JSON；stdout 专用于协议。当前 v1 schema、运行时操作白名单和错误／进度事件已在 DT-04 落地，详细契约见 [本机 JSON Lines 协议](desktop-rpc.md)。

| 消息 | 必填意义 |
| --- | --- |
| 请求 | `protocol_version`、`request_id`、白名单操作和经校验参数；`preview`、`apply`、`cancel` 分开，另有生命周期 `shutdown` |
| 进度 | 对应请求／作业 ID 和当前阶段；未知总量不伪造百分比 |
| 预览 | 一次性计划 ID、内容版本摘要、服务结构化结果和可否应用 |
| 应用请求 | 用户确认的计划 ID；应用前重算预览并复核本机输入 |
| 结果 | `preview`、`applied`、`cancelled` 或带机器错误码的 `failed`；关闭时收到 `shutdown_accepted` |

DT-04 当前在单个辅助程序进程内串行执行操作，提供写入边界前取消；进入写入后报告 `too_late` 并等待结束；`shutdown` 停止接收请求并等待已接受操作后退出。`sync(fetch/publish)` 因为会改动本机共享副本或远端，当前 RPC 明确拒绝这些选项的预览；桌面传输流程仍待实现。DT-04 的验收没有测试 Tauri UI、内置打包或启动自动恢复。DT-05 后续已建立 Windows Tauri／React 原型与 Python 3.14 sidecar；DT-06 有导航、状态总览和 Agent 只读识别入口，但干净账户安装与原生窗口集成尚未验收。

作业状态为排队、运行、等待选择、成功、失败、取消；它不代替应用／云端／加载状态。取消在事务提交阶段必须等待安全边界，不能强行终止后显示“已撤销”。启动时检查未完成事务，未恢复的问题按当前核心要求阻止新应用。

编辑保存只改变用户配置库；点击应用才写 agent。预览后目标被其他程序修改时拒绝旧计划并重新展示。只有核验通过才保存本机成功记录，加载核验仍需真实新会话。

## 9. 包字段与目标适配实例

目录包与 `.aiconfig` ZIP 归档共用 `manifest.json`。v1 的最低字段在 DT-13 写入 schema：格式版本、包 ID、完整内容标识、父内容版本、数据范围、适配器版本、文件列表、逻辑来源、依赖和排除报告。每个文件含归档相对路径、类型、大小与内容哈希。时间只用于展示，不用来判定哪份应覆盖另一份。

包 ID 标识一次导出，内容标识表示可核验的数据版本；相同内容可以有不同包 ID，但不因导出时间变化就被认定为配置变化。目录包自包含，不引用源设备文件或之前包；manifest 中没有 agent 根目录、账号令牌、设备基线或备份。

例如导入 `agent://codex/main/AGENTS.md`：

1. 客户端识别接收电脑的 Codex 实例；唯一匹配时生成默认目录映射。
2. 若有两个实例或包中是自定义实例，界面让用户选择目标，未选择时不写。
3. 将包中公共规则规划为该实例的受管区块，保留原文件区块外内容。
4. 比较目标当前版本与共同基线；存在冲突先处理，无基线不猜测。
5. 用户点击应用后再校验版本，备份、事务写入并核验内容。
6. 输出“文件已应用／加载未核验”，通过新会话问答后才能更新加载状态。

未安装 Codex 时，内容可暂存到客户端配置库，结果显示“待安装／未应用”，不创建一套假的已可用安装。源电脑记忆或规则正文中的历史路径不按字符串全局替换，无法表达为逻辑路径的内容在 DT-14 列出并处理后才能声称包不含本机路径。

导入不会因“全量”清空整个目标目录：没有包含的内容、排除项和未知文件不代表删除。导入决定与目标身份、基线、仅本机覆盖分别保存，源电脑的设备状态不复制到目标。

## 10. 服务端实施与接口

默认部署起点为用户提供的 Linux 服务器，容器运行 FastAPI、PostgreSQL 与挂载的私有包存储目录，通过 HTTPS 提供接口。先用文件存储完成单服务器闭环；如果服务器已有对象存储，再通过存储接口替换，不在首版引入必须运营的额外存储集群。平台、容量、域名和备份条件由 DT-30 核对后固定。

账户接入成熟 OIDC 身份提供方，客户端触发标准登录与回调；授权认证可能打开系统浏览器，配置、同步、恢复业务仍在客户端完成。DT-30 选择用户可运营的提供方，DT-32 实现身份验证与安全存储；未确定提供方前不宣称账号功能已接通。

云端采用客户端加密的完整归档。账号登录用于授权下载，首次新设备还需通过恢复材料或既有设备授权取得密钥。密钥只在客户端安全存储；服务端核对密文大小／哈希，客户端解密后再核对明文包。此设计减少服务端接触正文，但多出密钥恢复步骤；DT-33 必须实现并验收，不能留成没有流程的“以后再加”。

下列是待实现接口职责，路由在 DT-31 固定，不表示已有可调用 API：

| 接口草案 | 要做什么 | 失败／并发行为 |
| --- | --- | --- |
| `GET /v1/me` | 返回已验证用户的账号信息 | 无有效身份拒绝；客户端提供的用户 ID 不算认证 |
| `POST /v1/devices` | 为当前用户登记客户端设备 | 新设备不沿用发送端身份；可撤销 |
| `POST /v1/spaces` | 创建当前用户的配置空间 | 不跨用户复用配置空间 |
| `POST /v1/spaces/{id}/uploads` | 校验配额并创建上传会话 | 带幂等 ID；不立即产生可下载版本 |
| `GET /v1/uploads/{id}`、`PUT /v1/uploads/{id}/parts/{part}` | 查询进度、按约定块上传或续传 | 每次授权核验；重复请求不会重复追加字节 |
| `POST /v1/uploads/{id}/complete` | 核对密文，提交不可变版本并尝试更新 head | 数据库内比较 expected_head；冲突保留版本并返回冲突，半包不发布 |
| `GET /v1/spaces/{id}/versions`、`GET /v1/spaces/{id}/head` | 查询该用户配置版本与当前 head | 不根据上传时间覆盖分叉 |
| `GET /v1/versions/{id}/content` | 下载完成的密文包，支持重试／范围读取 | 不提供未完成或其他用户包 |
| `POST /v1/devices/{id}/receipts`、`GET /v1/spaces/{id}/receipts` | 保存／查看允许的应用摘要 | 不含实际路径或正文，不推断在线／加载 |
| `POST /v1/devices/{id}/revoke` | 撤销该用户的设备访问 | 历史内容保留，已撤销设备不再能访问受保护接口 |

同步过程为生成一致快照 → 加密 → 创建上传 → 上传／续传 → 完成确认 → 版本保存 → 另一设备下载 → 解锁与包检查 → 本机目录映射／差异 → 应用与核验 → 回执。每个阶段有独立结果；云端保存失败不丢本机包，回执失败不把已经完成的本机应用改成失败。

版本分叉时先下载并在客户端比较。服务器不读取密文正文来自动合并。历史恢复以历史内容生成新的版本；保留旧版本和当前版本，禁止强制覆盖 head 掩盖其他设备修改。清理历史需另行明确保留规则并预览。

## 11. 实施顺序与验收

1. 整理本机应用服务与设备状态位置，完成既有独立配置库的验证债务；保留现有 CLI 和用户未提交修改。
2. 桌面首条流程：安装、识别、迁入、预览、应用、状态、撤销；验证内置核心，用户不需终端或手改 JSON。
3. 统一包格式与离线导出／导入：空设备迁入、已有数据冲突、目录变化、多实例、损坏包、重复导入、失败恢复；完成 Windows 间及 Windows／macOS 真实设备验证。
4. 补齐其余现有功能的客户端入口；逐项扩展 skills／MCP／记忆范围，不将未支持内容伪装成全量恢复。
5. 接入用户服务器：登录、上传完成确认、下载、隔离授权、离线重试、并发版本冲突、历史恢复与密钥恢复。

离线迁移验收不依赖服务器；云端验收复用离线导入标准。每次验收记录实际日期、环境、版本、结果与未验证项。客户端功能、跨平台打包和真实 agent 加载通过前，不能把设计稿或文件生成当成功能完成。

按 [DESKTOP-TASKS.md](../DESKTOP-TASKS.md) 的 A～G 阶段执行，每项有明确工作、交付物和验收。离线版发布需 DT-01～29、DT-39～40 的离线要求；云端版增加 DT-30～38 的真实服务器要求。截至 2026-10-01，DT-01～04 已完成各自记录的本机范围；DT-05 已构建 Windows sidecar、Tauri release 与 NSIS 原型，但干净账户安装／启动未验收；DT-06～12 的状态总览、设置、迁入、编辑、核验、恢复、记忆映射及项目接续操作已接入原型并通过定向验证，原生窗口、远端传输与 Agent 新会话尚未验收；DT-13～40 尚待实施或验收。实际迁移包和服务器功能未交付。

首版不包含后台自动同步、自动更新、项目源码打包、自动安装 agent／依赖、登录文件迁移和未知原生会话恢复。这些功能不能出现在“全量迁移”或“拆包即用”的隐含承诺中。
