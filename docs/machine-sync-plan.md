## 3. 设计决策与取舍

### T-1 先定性、后采集：规则表加覆盖账本

- **选择**：把分类规范变成机器可读的规则表（带 ID）；所有采集先分类、再按动作处理；每个被访问的文件必有一条判定，落不上的显式记为「未定性」并列出。
- **理由**：现状是各采集器各挑路径，没挑中的文件没有任何痕迹（G-11）。
- **备选**：继续逐条补白名单。能补上已知缺口，但工具升级后新增的文件会让问题重现。
- **风险与缓解**：重构面大。分阶段：先「只观察」（账本，不改变采集结果），拿真机只读报告核对规则表，再放开采集。

### T-2 隐私：区分密钥与个人信息；命中密钥＝脱敏后保留

- **选择**：邮箱放行（D17）；命中密钥时替换值、保留文件，备份前列出，允许改选整份跳过。
- **备选**：整份丢弃（现状，会丢 skill 和人设）；原样带上（违反「备份不含凭据」）。
- **风险**：误判。缓解：有来源证据的第三方 skill 只对高置信度格式脱敏，赋值样式只提示。脱敏后的文件恢复时需重新填写，进「接下来要做的事」。
- **一致性**：必须同时改 G-06 列出的 6 处门禁，否则会出现「备份通过、恢复预检拒绝」。

### T-3 第三方 skill 原样带上的边界（与 D18 的关系）

- **选择**：带上 skill 目录内除 SK-05 以外的全部文件；SK-05（`.git`、`node_modules`、可执行文件、缓存）不带；Git 元数据不枚举、不计算大小，其它记录来源与大小。
- **为什么折中**：备份格式单文件上限 64 MiB（`bundle.py:19`）、整包 512 MiB（`bundle.py:20`），且整包在内存里拼装（`bundle.py:167`）。gstack 与 browse 里有 7 个约 98–115 MB 的可执行文件，合计约 690 MiB，装不下；它们是构建产物，不是 skill 内容。去掉后，CC Switch 里的 35 个第三方 skill 约 90–100 MiB（未压缩，按目录大小估算）。
- **备选**：① 提高上限并改为流式写入，把可执行文件也带上——体积翻数倍，且可执行文件在新机多半要重建，还可能被安全软件拦截；② 只记来源（我最初的建议，比现在少带源码）。
- **2026-10-09 已确认**：接受「源码全带、第三方可执行产物不带」；自建 skill 的可执行文件仍遵守 SK-05 的独立规定。
- **来源解析顺序**见接口契约 §5。读取 CC Switch 数据库的 skills 表可补全来源，但属于读取含供应商密钥的数据库，须单独授权（G11），不作为默认路径。

### T-4 `~/.claude/skills` 的批准链接与恢复落点

- **选择**：采集时只在白名单内跟随这一条链接；恢复时写入 Claude 原生位置 `~/.claude/skills/`，不写 `~/.cc-switch/`。
- **理由**：CC Switch 的数据库管理它自己的 skill 记录，直接往它的目录写文件会产生「有文件、无记录」。
- **风险**：新机若先装了 CC Switch 并已接管该链接，恢复会判定「路径含链接」，跳过并提示，不覆盖、不穿透。

### T-5 Claude 桌面端账号 skill：备份加导出式恢复

- **选择**：备份 `creatorType` 为 `user` 的 skill；恢复时不写应用缓存目录，而是为每个 skill 导出一个可上传的 ZIP，放进恢复报告文件夹，并在「接下来要做的事」里说明。
- **理由**：该目录是账号同步的缓存，应用会覆盖，写入没有支持保证。
- **验证**：第二台电脑登录后是否自动出现，决定导出是否多余；记入验收。

### T-6 项目范围

- **选择**：默认＝全部已登记且存在的文件夹（排除 worktrees、scratch）；项目内助手文件按白名单携带，不读取 Git。取代 D12（11 个核心项目）及原 Git 跟踪状态筛选。
- **影响**：信任类清单会变长（本机 Codex 登记 42 条），仍默认不恢复、逐次确认。

### T-7 版本与兼容

- **选择**：manifest `schema_version` 升为 2；顶层键不变，新字段只加在条目与 `reports/` 里；新版客户端可读 1 和 2；旧版客户端读 2 时在校验阶段拒绝，不写任何文件。
- **理由**：恢复预检遇到未知助手或类型会直接抛错（`preflight.py:190-191`），不升版本会让旧客户端在恢复中途失败。

### T-8 历史记录：分包与流式

- **选择**：勾选后另生成独立的历史备份包，与主包分开；写入改为流式，不整包进内存。
- **理由**：Claude 转录约 57 条，Codex 会话库合计约 730 MB 且还有会话文件，超过 512 MiB 的上限。
- **范围**：先做 Claude 转录（H1），再做 Codex 会话文件（H2）；恢复只新增不覆盖，不承诺续接。

### T-9 环境变量只导出脚本

- **选择**：生成 `restore-env.ps1` 与可读清单，不直接写注册表。
- **理由**：现有事务与撤销只覆盖文件，注册表写入无法纳入撤销。验收后可升级为一键写入。

## 7. 风险与回退

| 风险 | 影响 | 缓解与回退 |
|---|---|---|
| 脱敏误伤，第三方 skill 文本被改 | 违背「原样」 | 有来源证据的第三方只脱敏高置信度格式；赋值样式只提示；专家开关 `allow_secret_hit_paths` 可让指定文件原样带上 |
| 包体积与耗时增加（约 +100 MiB 未压缩） | 备份变慢 | 扫描结果缓存，`check_privacy` 不再对内容重复全文扫描；进度事件显示「正在扫描」 |
| 新版备份旧客户端打不开 | 旧版无法恢复新包 | 旧版在校验阶段拒绝，不写任何文件；旧 ZIP 在新版仍可恢复 |
| 批准链接被滥用 | 读到不该读的目录 | 白名单固定为两个目标；目标须在用户主目录内；目标自身不得是链接；目录内不得含链接 |
| 账号 skill 与云端副本重复 | 混淆 | 只导出、不写入；说明里注明「若已自动出现可跳过」 |
| 含占位符的 skill 被误用 | 带占位符运行 | 恢复后核验状态为「需要人工确认」，列入「接下来要做的事」 |
| 来源解析不准（把派生当原始） | 重装指引错误 | 记录 `confidence` 与 `evidence`；`guess` 级不用于自动判定 |
