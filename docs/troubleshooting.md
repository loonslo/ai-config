# 遇到问题

每条错误都固定回答三个问题：**发生了什么**、**原有数据是否保留**、**下一步怎么做**。错误编号在版本之间含义不变。

加 `--json` 会得到结构化的 `{"code","what","preserved","next_step","exit_code"}`。加 `--verbose` 会附加脱敏的技术详情。

## 错误编号速查

| 编号 | 含义 | 数据状态 | 下一步 |
| --- | --- | --- | --- |
| E1001 | 本机还没有完成首次设置 | 未写入任何文件 | 运行 `setup --apply` |
| E1002 | 目标工具目录不存在，或未选择任何共享范围 | 未写入任何文件 | 确认工具已安装并启动过一次，或改用仅公共规则 |
| E2001 | 无法连接配置源或 Git 远端 | 本机配置不受影响 | 检查网络与仓库地址；远端被删需在托管平台恢复 |
| E2002 | 配置源有未提交修改，或远端与本地已分叉 | 双方内容都保留 | 先处理配置源的修改，再运行同步；不要用强制推送 |
| E3001 | 目标文件受管内容与本机期望不一致（配置漂移） | 本机目标文件未被改动 | 运行 `diff` 选择处理方式，再重新同步 |
| E3002 | 目标文件缺失、格式错误或无法读取，无法核验 | 未生成成功回执，备份保留 | 检查文件是否存在、是否为符号链接、内容是否损坏 |
| E3003 | 写入目标文件失败 | 本批次已回滚，备份保留 | 关闭正在使用该文件的工具窗口后重试 |
| E4001 | 备份不完整或已损坏 | 当前文件保持原样 | 改用其他备份或手工恢复；确认前不要删除现有文件 |
| E4002 | 存在未完成的事务 | 已写入文件全部保留 | 运行 `doctor --recover` 处理后再继续 |
| E5001 | 状态尚未上报（警告） | 本机已应用的配置仍然有效 | 网络恢复后重试上报即可 |
| E9001 | 未分类错误 | 没有写入未经验证的文件 | 用 `--verbose` 查看详情，或运行 `doctor` |

退出码：`0` 正常或预览、`2` 尚未具备条件、`3` 待上报或网络问题、`4` 冲突、`1` 其他错误。

## 常见情况

### 显示“存在本机修改”或报 E3001

工具或你自己改过受管区块里的内容。脚本**不会**直接覆盖，因为那会丢掉你的修改。

先看看差在哪：

```text
.\ai-config.ps1 diff
```

然后三选一：

| 选择 | 含义 | 影响 |
| --- | --- | --- |
| `--choice share` | 共享到其他设备 | 更新共享模板中的这一个字段；还需要 `sync --publish --apply` 才发布到远端 |
| `--choice local` | 仅此设备 | 写入本机覆盖，只影响这台设备，不修改共享模板，也不会被提交；后续同步会一直使用该值 |
| `--choice restore` | 恢复共享值 | 先备份，再应用共享值；本机当前值可在 `undo` 中找回 |

不带 `--apply` 时以上都只是预览，不会写入。

**手改了受管规则区块（`AGENTS.md` / `CLAUDE.md` 里 `<!-- ai-config:begin -->` 到 `end` 之间的内容）时**，情况略有不同。`diff` 会把它列成一行"公共规则（rules）"，但**只提供两个选择**（`local` 会被拒绝）：

- `--choice share`：把本机这一版区块登记为共享值。工具会把这段文字**暂存**到 `state_dir/rules-share/` 下（`diff` 会打印路径），你还需要把它合并进 `common/` 下对应的主题文件，再运行 `sync --publish --apply` 发布，其他设备下次同步后才会得到。在共享内容真正保存并发布之前，`sync` 仍然会报 E3001——这是**有意的冲突保护**，不会假称已经共享成功。
- `--choice restore`：放弃本机改动，先备份本机文件，再把共享区块写回。之后重新跑一次 `sync --apply` 即可，本机改动可在 `undo` 中找回。这个决定是**一次性**的：预览不会消耗它，只有成功应用并核验通过后才会被清除。

完整闭环示例：

```text
.\ai-config.ps1 sync                     # 报 E3001，提示先运行 diff
.\ai-config.ps1 diff                     # 列出"公共规则（rules）"这一行
.\ai-config.ps1 diff --choice restore --apply
.\ai-config.ps1 sync --apply             # 恢复共享区块，退出码 0
```

只有受管区块之外的文字（你自己的段落）不会被触碰。

### 显示“需要启动新会话”

这不是错误。文件已经写入并**重新读取核对过**，只是工具要重开才会加载新设置。重开 Codex 或 Claude 即可。

### 什么都没有变化

说明本机受管内容和共享值已经一致。注意：

- 零变更预览**不代表已生效**。
- 想确认远端有没有新内容，加 `--fetch`（拉取的是**配置源**，不是记忆仓库）。
- 本机保存的共享修改只有加 `--publish` 才会离开这台机器。
- 不带 `--apply` 的 `sync` 只预览，不会写文件，也不会发布或上报。

### 显示 [E5001] 状态尚未上报

这不是配置失败。本机配置已经写入并核对一致，只是回执没能推到配置源的 `device-receipts` 分支（离线、无权限或配置源没有远端）。退出码是 3。

- 本机配置和已应用的设置都保留，不需要重新同步。
- 网络或权限恢复后再运行一次 `sync --apply` 即可补报。
- 如果配置源本来就没有远端，会显示“未配置，已跳过”，退出码仍是 0。

### 输出出现乱码

脚本在输出被重定向到管道或文件时固定使用 UTF-8。若仍然乱码，说明读取端按本机代码页解码了；请按 UTF-8 读取，或设置 `PYTHONIOENCODING=utf-8`（该变量存在时脚本会完全遵循它）。

### 记忆相关的报错

只想统一配置的话，不需要理会记忆功能。

- `记忆同步：未启用` 是正常状态，不是错误。
- 记忆源被标为“暂不可启用”时，看该行下方的“说明”：
  - **发现疑似凭据** — 同步会停止且不输出匹配内容。把凭据从源文件移除，或在该项目条目加 `"exclude": ["文件名.md"]`。
  - **不支持的文件类型** — 目录里有非 `.md` 文件。移走或加入排除列表。
  - **路径碰撞** — 文件名存在大小写或 Unicode 归一化冲突，需要手动改名。
- 已经进入共享历史的敏感文件不能靠排除解决，必须清理历史。

### 关闭记忆后会不会删掉我的记忆

不会。`memory-setup --disable` 只是不再同步，本机原始文件保持原样。

### 撤销上一次配置应用

```text
.\ai-config.ps1 undo              # 列出最近的操作
.\ai-config.ps1 undo --index 1    # 预览恢复第 1 条
.\ai-config.ps1 undo --index 1 --apply
```

不需要找 UUID 或备份编号。恢复前会核对备份内容和目标文件在该操作之后是否又被改过；备份损坏会直接拒绝。**撤销只影响本机**，不会把这个状态推成共享最新值。

配置恢复和记忆快照恢复是分开的，互不影响。

### 中断了怎么办

先看 `doctor`：

```text
.\ai-config.ps1 doctor --local device.json
```

它会列出未完成的事务和当前来源状态。确认日志里的 `ROLLBACK_REQUIRED`、外部修改和备份内容后，再决定恢复还是重做。**不要只删除锁文件**——锁文件被删掉不代表写入已经回滚。

### macOS 提示没有执行权限

```text
chmod +x ai-config.command
```

### 提示 Python 版本过低或缺少依赖

启动脚本会给出对应系统的具体命令。手动执行是：

```text
python -m pip install -r requirements.txt
```

macOS 上如果只有 `python3`，把命令里的 `python` 换成 `python3`。

依赖装在项目自己的独立环境里，不会污染系统 Python，也不会修改 PATH 或全局包。

## 还是解决不了

```text
.\ai-config.ps1 status --json > status.json
.\ai-config.ps1 doctor --local device.json > doctor.txt
```

把这两份输出（不含凭据）留档。`--verbose` 的输出已经脱敏，但分享前请再确认一遍。
