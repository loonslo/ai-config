# AI Config 桌面客户端

## 当前方向（2026-10-08）

桌面客户端是唯一面向用户的入口，只保留基于 `ai-machine-bundle` ZIP 的原样备份与恢复。用户在旧电脑选择助手与工作文件夹，检查后生成本地备份；自行传输到新电脑，在客户端检查目录、冲突与选项后恢复。云端、服务器及 Git 同步不推进，不提供用户内容托管。

当前桌面端已接入备份、恢复、文件核验与撤销引擎。原 `.aiconfig` 迁移界面已替换，旧格式不进入新恢复流程。命令脚本仅保留为历史开发工具，不是交付入口，不要求用户安装 Python、Git 或打开终端。Windows 安装包重建及实际检查见 [验收记录](docs/acceptance.md)；真实跨机、助手加载和 Mac 验收仍未完成。

Windows x64 预览安装包：前往 [GitHub 0.3.2 Release](https://github.com/loonslo/ai-config/releases/tag/v0.3.2) 下载 `AI-Config-0.3.2-Windows-x64-setup.exe`。SHA-256：`8701613747a6f4b22187c65202c0628451fa4b4fca9b662f88d30d493ac7e1e0`。该版本尚未完成原生升级和真实跨机加载验收，代码签名未验证。

使用方法见 [一页上手](docs/quickstart.md)，当前实施记录见 [桌面离线迁移任务](docs/desktop-offline-migration.md)。

## 当前方向（2026-10-02）

当前实施计划是[换机迁移工具包](MACHINE-MIGRATION-TASKS.md)：先备份，再在新电脑恢复 AI 助手配置、记忆和项目状态。桌面客户端、服务器／云同步及受管区块同步已冻结，因为本轮优先解决离线换机迁移；下文相关内容保留为历史开发预览，不代表新方案已实现或验收。

备份操作见[一页上手说明](docs/quickstart.md)；双击与跨机恢复仍待验收。

在客户端管理多个 AI agent 的共享规则，并以离线迁移包或加密服务器传输到另一设备。当前是开发预览版本；Windows 安装、Mac、真实账号与服务器验收仍有待办，见 [实施与边界](docs/desktop-local-implementation.md)，不能视为正式发布。

## 客户端操作

1. 安装已取得的 Windows 预览安装包并启动 AI Config。首次使用在“Agent 与规则”只读识别目录，再确认创建本机配置库；已有旧 device.json 在“可选能力”先预览迁入，原件和备份保留。
2. 在“迁移”检查原有规则，逐项选择迁入、保留或跳过。编辑共享规则先保存配置库，再单独预览并确认应用到 Agent。
3. 在“迁移”选择导出位置和范围，检查后生成 `.aiconfig` 或自包含目录。默认仅规则、已支持共享设置和 Agent 声明；skills、MCP、记忆和交接须先明确采集，并启用对应范围。
4. 把离线包复制到另一设备，打开／拖入／双击包进入检查；完成目标实例选择与冲突决定，再确认导入。没有 Git、没有独立 Python、不登录也可使用打包客户端的本机与离线功能。
5. 文件写入后看“总览”与“历史恢复”。需要证明 Agent 已读取规则时，在真实新会话按“加载核验”提示回答；落盘不等于加载。目标有后续修改时撤销会停止，保留现场。

用户数据在 `~/.ai-sync/`：store 是配置源，device.json 保存本机路径，state 保存基线、备份和事务。升级程序不应移动这些数据。`AI_CONFIG_HOME` 可指定本机绝对路径。安装／卸载不会以全量迁移名义删除未知 Agent 文件。

## 服务器同步

先由运维部署 [服务器与 OIDC](docs/server-deployment.md)，提供 HTTPS 地址、签发方、公开客户端 ID 和 API audience。客户端“云端同步”逐步完成浏览器登录、创建／选择空间、首台生成密钥并独立备份恢复材料。另一设备先登录，再用同一空间恢复材料解锁。令牌和数据密钥保存在系统安全存储，不保存在配置库。

上传选已导出的完整包和实际共同父版本，预览后确认加密上传；中断可重试续传。云端分叉保留双方。下载历史版本先解密与检查，再进入离线映射／冲突／导入。恢复历史后重新导出为新版本上传，不直接回退服务器 head。账号登录不能找回已丢失的解密密钥。

服务器代码、客户端流程和部署文件已提供，但真实服务器、OIDC、PostgreSQL 并发和跨设备联调未验收，详见 [架构与协议](docs/server-architecture.md)。不承诺服务器已运行。

## 支持范围

| 内容 | 当前范围 |
| --- | --- |
| 规则 | 已登记入口的受管区块／文件，目标外部原文保留 |
| 设置 | Codex / Claude allowlist 共享字段，本机覆盖默认不导出 |
| skills | Codex / Claude 选定技能的文本与受支持资源；复制部署，外部链接及二进制资源拒绝；实机识别待验收 |
| MCP | Codex 非敏感 stdio / HTTPS 字段，仅环境变量名称；依赖缺失只保存配置库，不执行命令；连接未核验 |
| 记忆 | 已校验 Claude Markdown 可映射恢复；Codex 快照仅参考 |
| 交接 | 已登记库的校验文档，保留项目、源码版本和依赖锁身份；“可选能力”无 Git 查看正文与缺项，未核验源码／依赖不算完整接续 |
| 服务器 | OIDC、账号隔离、客户端加密、续传、版本和回执的本地实现；真实部署待验收 |
| 平台 | Windows 构建；Mac 构建流程已提供，实际安装包与平台支持未验收 |

不迁移认证、Cookie、密钥、会话数据库、整个工具运行目录、源码或外部程序依赖；不自动安装 agent、后台同步或自动更新。其他 Agent 的规则入口依原有适配器范围，WorkBuddy/TRAE 等需要实际会话核验。
